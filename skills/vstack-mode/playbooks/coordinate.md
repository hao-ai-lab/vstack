# coordinate

Run the units of any route through briefs, workers, acceptance and the unit table. The loop adapts pstack's orchestrate playbook (topology and supervision), with swarm's rule for results that miss their method, arena's base-and-graft for key units, and reflect and correct for the batch review; attribution is in [NOTICE](../../../NOTICE.md).

The coordinator writes briefs, accepts hand-backs and merges the unit table. It does not census, model or write specifications itself. Each unit gets one fresh worker and one output directory; a worker cannot see another worker's directory.

## The loop

1. **Plan.** Write the units from S1 to a plan file, one unit id per line, and enter each in the [unit table](../../../templates/unit-table.tsv) as `queued` with its own `output_dir`, a `batch` and `key`. A batch is the set of units sent with one brief template; a changed template starts a new batch.
2. **Brief.** Generate each unit's brief with `python3 scripts/make_brief.py FIELDS --out BRIEF.md` from the [task brief template](../../../templates/task-brief.md) or a domain template ([spec check](../../../templates/briefs/spec-check.md), [triage](../../../templates/briefs/triage.md), [reproduction](../../../templates/briefs/reproduction.md), [instance writing](../../../templates/briefs/instance-writing.md), [comparison](../../../templates/briefs/comparison.md)): goal and why, inputs, absolute writable paths, forbidden paths and actions with the blind decision, outputs written as you go, done evidence and the hand-back block. Write a fresh fields file per unit and never derive a brief from another brief; the generator refuses a field that fills no slot, and the checker refuses a brief edited after generation. Let the generator compute every row count (`{{rows of ...}}`), table header (`{{header of ...}}`) and copied sentence (`{{cell of ...}}`); declare id families (`ids:`), output columns that name ids of another table (`ref:`) and markers that must stay (`literal:`). Send the brief only when `python3 scripts/check_brief.py BRIEF.md` prints OK. A unit whose done evidence you cannot name (an exact command and its expected last line, or a pattern for a line that carries counts) is not scoped yet. For a blind unit, use a template whose method is fixed text, so that the coordinator, who has seen the answer key, does not write the method.
3. **One unit first.** Send the batch's `first_of_batch` unit alone and take it through work, hand-back and acceptance. Fix the brief template from what went wrong, then send the rest of the batch. The unit-table check fails while another unit of the batch has left `queued` before the first unit is `accepted`. On near-identical cheap units, the first unit is the whole test.
4. **Fan out.** One fresh worker per unit, the brief pasted in full. In the same step set the row to `running` with the brief's path in `brief` and the id the harness gave the worker in `owner`; a unit is running only once both are recorded. Look a worker up in the table before you send it a message, and never report a unit as running from memory. `python3 scripts/check_unit_table.py UNITS.tsv --plan PLAN --briefs BRIEFS_DIR` refuses a brief in the brief folder that no row names (written but never sent), a row whose brief has no worker, a unit past `queued` without its brief, and a worker id recorded for two units.
5. **Hand-back.** Check each reply with `python3 scripts/parse_handback.py REPLY --brief BRIEF.md`. When several workers change one tree, give each its own files or globs as writable paths (never the whole tree to two workers) and add `--changed` with the tree's `git -c core.quotepath=off status --porcelain=v1 --untracked-files=all`, `--tree` and every other worker's brief as `--sibling`. Return a reply unread when its block does not parse, a claimed last line does not end its log, a done-evidence command is missing, a written file or a changed file lies outside the writable paths, a changed file is not reported, or an id that a `ref:` names is not in its table. Otherwise set the row to `pass`, `issues` or `blocked`, with evidence paths inside its output directory.
6. **Accept.** Rerun the done evidence from a clean copy, read the artifacts rather than the summary, read the source behind a sample of rows, and apply the stage's exit checks and the [independent review](../../../docs/layer-0.md) of Layer 0. Only then set `accepted`. A unit that fails acceptance is re-spawned once with a fresh worker and a corrected brief; after a second failure it stays `blocked`, a recorded gap that never counts as a pass.
7. **Close the batch.** `python3 scripts/check_unit_table.py UNITS.tsv --plan PLAN --final --briefs BRIEFS_DIR` passes only when every unit is `accepted` or `blocked` and the table and the plan list the same units.
8. **Review the batch.** Follow [end-of-batch review](#end-of-batch-review) before writing the next batch's briefs.

## Two writings for key units

A unit marked `key` is written twice: the same brief goes to two workers in separate output directories, each brief `Blind: yes` and listing the other's directory. Neither writing is used before the comparison.

1. **Compare.** Fill a [writing-compare table](../../../templates/writing-compare.tsv), one line per pairing of a row of writing A with a row of writing B: `same`, `narrower` or `broader` (row A claims less or more than row B), `overlap`, or `only_here` with one side empty. Mark `contradiction`; for each contradiction read the code and record `who_is_right` (`a`, `b` or `neither`) with the site read in `note`.
2. **Check.** `python3 scripts/check_writings.py COMPARE.tsv --a A.tsv --b B.tsv` fails unless every row of both writings appears and every line is well formed.
3. **Pick a base and graft.** Keep as the base the writing a maintainer can extend most easily, with fewer wrong rows. `--base a` or `--base b` lists the other writing's rows to graft: rows only it has, rows broader than the base's, overlaps to merge and contradictions it wins. Fold each graft in by hand so the result reads as one writing; fix every contradiction where neither is right from the code.
4. **Divergence.** When few rows are `same`, the brief was under-specified: rewrite it and run both writings again rather than averaging them.

Put the comparison table in the unit's evidence; the unit-table check requires it for a key unit.

## End-of-batch review

Read every hand-back of the batch, its `rules broken` lines and the coordinator's acceptance notes and lessons. Group the errors into classes. A class seen twice, in this batch or an earlier one, becomes a check or a template field in the same round, at the highest level that works: a script that fails first, then a template field a checker requires, and text last. Prove the new check fails on the real past mistake, then add a row to the [rule registry](../../../docs/rule-registry.md) with the rule, the error it prevents, its enforcer and the date. An error that recurs although the registry lists its rule was not enforced strongly enough: move it to a higher level in the same change. Text alone is not a fix.
