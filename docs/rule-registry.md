# Rule registry

Each row pairs a rule with the error it prevents and the script or template field that enforces it. This is the rule-to-enforcer table that the [repeated-mistakes rule of Layer 0](layer-0.md) and the S5 exit checks update. At the [end of each batch](../skills/vstack-mode/playbooks/coordinate.md#end-of-batch-review), an error class seen twice gets an enforcer and a row here in the same round; an error that recurs although its rule is listed means the enforcer is too weak and moves to a higher level (a failing script before a required field, a required field before text). Drop a row only when its error can no longer happen. The adaptation of pstack's correct and reflect skills is credited in [NOTICE](../NOTICE.md).

`Documented-only` marks a field that no script checks yet.

## Coordination and hygiene checks

The checks are read-only, print `ERROR <where>: <reason>` lines and end with one `OK ...` or `FAIL ...` line; exit 0 means valid, 1 invalid or unreadable input, 2 bad usage. `--help` lists every rule. Each is also `vstack gate <name>`. The generator `make_brief.py` writes one file and follows the same conventions.

### make_brief.py

```sh
python3 scripts/make_brief.py FIELDS --out BRIEF.md [--template FILE] [--force]    # vstack gate make-brief
```

Generates a brief from `templates/task-brief.md` or a domain template in `templates/briefs/` (named by a `template:` line of the fields file or `--template`). A slot is `<name>` or `<name: guidance>` outside HTML comments; FIELDS holds one `name: value` line per slot, or `name:` followed by a block indented by two spaces. A slot alone on its line takes a block, and an empty block drops the line; a slot inside a line takes one line. Outside comments, `{{rows of /a.tsv /b.tsv where COL=VALUE}}` becomes ``N rows of `/a.tsv` and `/b.tsv` where `COL=VALUE` `` counted with each file's own header skipped (blank and `#` lines never count; conditions `COL=VALUE` and `COL!=VALUE` joined by `and`), `{{header of templates/X.tsv}}` becomes that template's header with its source, and `{{cell of /t.tsv column NAME where KEY=VALUE}}` the one matching cell. It refuses a field that fills no slot (a leftover of another fields file), a slot without a field, a value it cannot compute, and a result that `check_brief.py` refuses, and then writes nothing. The brief is written atomically with a stamp (the template's, the fields file's and its own SHA-256); a second run gives the same file, and an existing file that was not generated or was edited since is overwritten only with `--force`. A self-test example of a fields file is `scripts/tests/make_brief/fields.txt`.

### check_brief.py

```sh
python3 scripts/check_brief.py BRIEF.md [--template FILE] [--hand-written]    # vstack gate check-brief
```

Checks a brief generated from `templates/task-brief.md` or a domain template. The sections and the hand-back fields come from the template, not from a list in the checker. It requires: the generator's stamp, its text unchanged and its template and fields file unchanged since (`--hand-written` accepts a brief without a stamp and says so in the OK line); the seven `##` sections present once, in order and not empty (HTML comments do not count); no placeholder left: a slot of the templates anywhere, `__NAME__`, `{{...}}`, `TODO`, `TBD` and `FIXME` anywhere, `<...>` in prose and in done-evidence commands and exact or suffix lines, a `<...>` holding a space in code, and a slot not closed on its line, while a one-word `<file>` or `slides/<id>.html` in code is usage syntax and text declared with ``literal: `TEXT` `` is exempt; every writable path absolute and canonical, globs (`*`, `**`, `?`) and `except PATH` items allowed; exactly one `Blind: yes` or `Blind: no`, a blind brief listing the absolute paths not to open, none of which contains a path another section gives the worker; outputs written as you go; at least one `command:` followed by `last line:` (exact), `last line ends with:` (suffix) or `last line matches:` (a regular expression for the whole line), no exact or suffix line ending in `=` or `:`, no pattern that accepts an empty, FAIL or ERROR line; a done-evidence run of `scripts/grade_findings.py` when "What to produce" names finding records; the hand-back block in the hand-back section. It also checks facts the brief states: each ``N rows of `FILE`...[ where `COL=VALUE`]`` is recounted (each file's own header skipped), and a row count in prose that is not tied to files fails; each match of an ``ids: `REGEX` from `FILE` column `NAME` `` or ``ids: `REGEX` only `ID`, ...`` declaration must be one of those ids; each ``ref: `OUTPUT` column `NAME` -> `TABLE` column `NAME` `` names an existing table and column; each ``header `...` (from `TEMPLATE`)`` equals that template's header. It checks form and stated facts, not whether the brief is right; outputs that hold finding records without saying so, numbers written in words and ids of an undeclared family are not detected.

### parse_handback.py

```sh
python3 scripts/parse_handback.py REPLY [--brief BRIEF.md] [--root DIR] [--ref OUTPUT COLUMN TABLE ID]
    [--changed FILE [--tree DIR] [--sibling BRIEF.md]]    # vstack gate parse-handback
```

Extracts the block between `BEGIN HANDBACK` and `END HANDBACK` and prints its fields as TSV; the fields are those of the block in `templates/task-brief.md`. Requires one verdict (`PASS`, `ISSUES` or `BLOCKED`), one or more `check:` lines each followed by `log:` and `last line:`, and one or more `version:`, `written:` and `rules broken:` lines (`none` alone). Each log must exist and end, ignoring blank lines, with exactly the claimed last line; each written file must exist. With `--brief`, every done-evidence command must be reported (whitespace-normalized; a `BLOCKED` reply may omit one), a `PASS` verdict needs every expected last line (exact, suffix or whole-line pattern), and written files must lie under the brief's writable paths, globs and `except` items honoured. Every `ref:` of the brief and every `--ref` is checked: each id in that column of the output (cells split on `;`, `,` and spaces; empty, `none`, `n/a` and `-` skipped) must be an id of the table column; a relative output resolves against the brief's first writable directory, and a missing output fails unless the verdict is `BLOCKED`. `--changed` takes the files changed in a tree that several workers write (`git -c core.quotepath=off status --porcelain=v1 --untracked-files=all` output, or one path per line, relative to `--tree`): each must be writable by exactly one of this brief and the `--sibling` briefs, and each one this brief may write must be reported as written (a deleted file or the source of a rename only needs to be writable). It trusts the log files; it does not rerun commands.

### check_unit_table.py

```sh
python3 scripts/check_unit_table.py UNITS.tsv (--plan PLAN | --no-plan) [--final] [--root DIR] [--briefs DIR]    # vstack gate check-unit-table
```

Requires the exact `templates/unit-table.tsv` header, unique unit ids, a status from `queued`, `running`, `pass`, `issues`, `blocked` and `accepted`, a batch, `yes` or `no` in `first_of_batch` and `key`, and an output directory not shared with or nested in another row's. Past `running`, a row needs an owner and evidence paths that exist inside its output directory; a key unit names two owners and, unless blocked, a writing-compare table (recognized by its header) among its evidence. Each batch has one first unit, and no other unit of the batch leaves `queued` before the first is `accepted`. The plan (one id per line, or a TSV with a `unit_id` column) and the table must list the same units. `--final` also fails on any unit not `accepted` or `blocked`, and reports blocked units as gaps. The table is also the dispatch record: `brief` is the brief the unit's worker was sent and `owner` the id the harness gave that worker (not a role or slot name). A unit past `queued` needs a brief that exists; a row that names a brief needs its worker, so a brief written but never sent fails; a worker id may appear in one unit only and a brief in one unit only, so a message for a worker reaches one unit. `--briefs DIR` also fails on a brief file (`*.md`, recursively) in DIR that no row names. A table with the 0.123.0 header (no `brief` column) is refused with that hint. It does not judge the evidence, and it cannot see a brief kept outside DIR or a message sent without looking at the table.

### check_writings.py

```sh
python3 scripts/check_writings.py COMPARE.tsv --a A.tsv --b B.tsv [--id-column NAME] [--base a|b]    # vstack gate check-writings
```

Checks a `templates/writing-compare.tsv` table against two writings whose rows are identified by `--id-column` (default: the first column): known relations (`same`, `narrower`, `broader`, `overlap`, `only_here`), both sides filled except for `only_here`, rows that exist, no repeated pair, and for each contradiction `who_is_right` (`a`, `b` or `neither`) with a note; every row of both writings must appear. `--base` prints the rows of the other writing to graft. Whether a relation is right is for the reader to judge.

### check_hygiene.py

```sh
python3 scripts/check_hygiene.py [ROOT] [--allow FILE] [--deny FILE] [--untracked] [--walk] [--commits BASE..HEAD]    # vstack gate check-hygiene
```

Scans the files Git tracks under `ROOT` (default: this repository; `--untracked` adds files not yet added, `--walk` scans a tree without Git) and skips binary files. It reports CJK, kana, Hangul and full-width characters; personal home directories of Linux, macOS and Windows; session, share and artifact links of chat tools; terms from `--deny`; text that is not UTF-8; and case data outside `data/`. File names are checked as well. Keep the `--deny` list of private terms (internal case names, host names, task ids; a line starting with `re:` is a regular expression) outside the repository. The allow-list (default `scripts/hygiene-allow.tsv`, columns `rule`, `path`, `reason`) excuses one rule in files matching a glob; every entry needs a reason and must still excuse a hit. Run it before every push.

With `--commits BASE..HEAD` it also scans what a push of that range publishes: every file version that a commit of the range adds or changes, also when a later commit of the range cleans or deletes it again, and every commit message. Such hits read `HIT <rule> <commit>:<path>:<line>` or `HIT <rule> <commit> message:<line>`; allow entries apply to file versions by path and never to messages. A range with no commits is an error, so a reversed or mistyped range fails instead of passing. Before a push, run it on the range the push publishes, for example `--commits origin/main..HEAD`. The summary line ends with `allowed` when the scan passes (`OK hygiene: ..., 0 hits; N allowed`) and with `files` when it finds hits (`FAIL hygiene: ...; N files`), so a brief can match it with `last line ends with`; the note that `private-term` did not run (no `--deny`) moved into the middle of that line.

**Case data** is the working material of one verification campaign on one code base: scan, unit and census tables with real rows, finding records, hand-backs, checker and run logs, traces, and the models and configurations of a case. It lives in `data/` (the mirror of the specification sheet) and nowhere else; the published bug ledger `bugs/verified-bugs.csv` is a product of the project and is allow-listed. The check recognizes case data by file type (`.tsv`, `.csv`, `.jsonl`, `.ndjson`, `.log`, `.out`, `.trace`, `.tla`, `.cfg`, `.smt2`) outside `data/`; templates and test fixtures are allow-listed. Case data pasted into a Markdown or code file is not detected; review catches it.
